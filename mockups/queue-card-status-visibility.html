Per-service status visibility — mockup

Recommended design: each service is its own row with a glyph + color + status pill; only the in-service row gets the bold green bar + tint, done rows go quiet-blue, waiting stays amber, paid fades. Reuses the app's existing STATUS_CHIP palette. (This file is a mockup — nothing in the live app is changed.)

Notes

Why this works: every status is carried by three redundant cues — shape (○ ● ◍ ✓), color, and a text pill — so it reads instantly and is color-blind safe.

Effort: Small–Medium. Two render maps (queue.js + turns.js) + one shared serviceLineStyle(status) helper in status.js. No change to the data/sync/status model — per-line status already exists. Standard version-trio bump; no Worker deploy.

Trade-off to eyeball: each service is now its own row (~+6px), so multi-service cards get a little taller — that's the price of the clarity. Pills use short labels (Wait / In Svc / Done / Paid) to survive narrow iPad widths.
