## How the audit is run (method)

Each section is audited with a **multi-agent workflow**: 5–7 independent reviewers each take a distinct lens (correctness/money, data-integrity, silent-failure, race-condition, stale/dead code, ergonomics, improvements) over a coherent code slice, producing structured findings with `file:line` evidence. Every raw finding then goes through an **adversarial verification** pass (a separate agent tries to *refute* it and adjusts severity). Only `confirmed` findings are reported; `false-positive`/`none` are dropped.

**Cadence:** collect findings per section → report → fix the HIGH / easy-high-ROI items as hotfixes (with owner approval) → continue. Verify each fix in the preview (or in isolation for pure logic) before committing.

**Operational quirk:** a few runs had a transient block of verification agents fail to return structured output (`§5`, `§8`). Fix: **resume the same workflow run** (`Workflow({scriptPath, resumeFromRunId})`) — cached reviews + successful verifications return instantly; only the failed ones re-run.

**Standing rules** (from owner): commit freely; **`git push` needs explicit owner OK each time**; **`wrangler deploy` is the owner's job** (walk them through it). Verify in preview; a disconnected preview tab's dispatch stays local, but the preview's WebSocket reaches the **prod** DO, so never dispatch test writes that would hit production.

## 🔑 Decisions made (with rationale)

1. **`config.set` guard done as its own staged change** (not lumped with quick wins) given it touches the core write path + DO. Built backward/forward compatible so it was safe in any client/Worker deploy order. ✅ shipped v4.13.
2. **Cash tips go STRAIGHT TO THE TECH** (owner confirmed) → the cash drawer's `tenders.cash` (bill-only) is already correct; **do NOT** change it to `cashReceived − change` (that would create a phantom *short*). §8 "B1" is a non-issue for this salon.
3. **Cash sales ALWAYS via the Pay screen** (owner confirmed) → §8 "B3" (quick Mark-Paid cash invisible to drawer) doesn't apply in practice.
4. **Cash refunds DO happen** (owner confirmed) → built the §8 "B2" Cash-Out checkbox. ✅ shipped v4.15.
5. **"Paid" status policy = P0** (owner-requested): decide whether staff may mark Paid manually, consolidate the two divergent "→ paid" paths into one (tenders + gift draw-down + audit), and define a **safe reversal/un-pay** flow. See PRIORITIES.md. Ties together §5/§7/§8 findings.
6. **Gift-card A3** (refund doesn't reverse the redemption) **deferred** — it's part of the P0 pay-path consolidation; best paired with the §10 Square pay-flow audit.
7. **Kept `dedupByLabel`** (it's covered by a test) and just corrected the false docs claim, rather than deleting tested code.
8. **`integer-cents`** money model **deferred** (existing P3) — float drift is absorbed by `toFixed`/`Math.round` at charge/display boundaries; revisit only if real drift appears (or do it natively in TurnDesk).
9. **Backend (`worker.js`) cleanups deferred to §13** (dead legacy WS relay, unbounded `deletion:` markers, probabilistic audit pruning) so client and backend changes don't interleave mid-audit.

### MEDIUM (worth doing; several fold into the P0)
- **§2 — 3 permission toggles are inert:** `viewReports` / `manageStaff` / `manageServices` are editable in Settings but **never enforced** by any `canDo()`. Either wire real gates or remove the toggles.
- **§4 — index-based item/fee edit/delete:** `updateItemField`/`removeItem`/`updateFeeField`/`removeFee`/`squarePushItem` key off the render-time array index; after a remote reorder (Settings list doesn't re-render on inbound `config.set`) an edit/delete can hit the **wrong row**. Fix: key by the existing `id` (services already do).
- **§4 — Square pull misclassifies services→fees:** any catalog item whose name contains "fee/charge/surcharge" is routed to FEES regardless of `product_type` (silent). Classify on `product_type`/category.

- **§5 — edit-lock close-overwrite + no override:** `closeGroupAssignModal` auto-saves with no stale check (can overwrite a concurrent edit); operator can't override a stuck lock.
- **§5/§8 — gift draw-down skipped via modal status-cycle finalize; gift reversal bypassed on modal reopen** → **P0** pay-path consolidation.
- **§7/§8 — refunding a gift-card-paid ticket doesn't reverse the redemption** (income drops, card stays drawn down) → **P0**.
- **§8 residual — true same-instant concurrent redemption of the SAME card across two devices** is still last-writer-wins (A2 closed the offline-replay clobber, not this). Would need per-redemption-id merge (cards have no redemption ids today).
